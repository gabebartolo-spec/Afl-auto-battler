# How CI splits the Godot test suites across parallel jobs
# (.github/workflows/tests.yml). One line per shard: its number, a colon, then
# the suites it runs. Every suite in tools/run_tests.sh must appear in exactly
# one shard; tools/check_ci_shards.sh checks that on every CI run, so a new
# suite cannot quietly skip CI.
#
# Balanced (2026-10-06) on the mean per-suite time of three full runs on
# GitHub's runners (two before #331, one after): about 528 s of suite time a
# shard, plus about 130 s of import and setup. Runner speed varies a lot between
# runs (career took 274 to 408 s), so treat these as rough. Slowest suites:
# career 361, match_visual 274, match_game 285, league_balance 226, balance 164,
# club 161, calibration 124, coach_market 104; the rest under 90.
# A new suite goes in the shortest shard; re-balance when one gets much slower.
